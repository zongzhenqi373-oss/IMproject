## 1. 项目背景

### 1.1 课题题目

**即通 App**：具备 C2C 的文本和图片收发能力，使用 AI 编程工具从 0 到 1 搭建一个全新 App。

### 1.2 实施策略

在现有 IM 项目（Qt 客户端 + Windows C++ 服务端）基础上做**跨平台落地**：协议（protobuf）、注册登录（加盐哈希）、心跳、互踢、离线消息等已验证能力直接平移；新增图片/文件消息、消息漫游、已读回执、输入中、本地搜索、传输加密；服务端重写为跨平台并发架构。

### 1.3 目标定位与运行环境

**目标：可落地的跨平台 IM App**（非一次性 demo）。

| 端 | 运行方式 | 说明 |
|---|---|---|
| Android 客户端 | **Android Studio** 运行（模拟器或真机） | Kotlin + Jetpack Compose |
| 服务端 | **VS Code** 内一键构建运行 | 跨平台 C++（CMake），macOS / Linux / Windows 均可构建 |
| 本次现场演示环境 | 本机 macOS：Android Studio 模拟器 + VS Code 服务端 | 只是运行组合之一，架构不绑定 Mac |

### 1.4 过程要求

体现"AI 不断迭代、逐模块优化至合理方案"的过程：
- git log 保留"裸 struct→pb、无锁→并发治理、Windows 专用→跨平台"的演进轨迹
- **每个里程碑单独 commit**（别一把梭），让迭代脉络可追溯
- 设计文档维护"方案 A/B 对比与取舍"决策记录

## 2. 术语

| 术语 | 含义 |
|---|---|
| C2C | Client to Client，单聊 |
| 漫游 | 换设备/重装后从服务端拉取历史消息 |
| pb | Protocol Buffers |
| KV | 键值存储（本项目指 MMKV） |

## 3. 功能需求

### 3.1 功能列表（MoSCoW 优先级）

| 编号 | 功能 | 优先级 | 说明 |
|---|---|---|---|
| F1 | 用户注册 | **Must** | 现有能力平移：昵称/手机号/密码，唯一性校验 |
| F2 | 用户登录 | **Must** | 手机号+密码；登录安全设计是考察点 |
| F3 | 实时消息通道 | **Must** | TCP 长连接 + protobuf；在线即时送达 |
| F4 | 后台转发 | **Must** | 服务端按在线状态转发；离线入库、上线补发 |
| F5 | 文本消息收发 | **Must** | 单聊文本，UTF-8 |
| F6 | 图片消息收发 | **Must** | 选图→压缩→传输→落盘→展示 |
| F7 | **文件传输** | **Must** | 任意类型文件，分块传输 + 进度 + 落盘 |
| F8 | **消息漫游** | **Must** | 服务端全量历史，分页拉取，与本地合并去重 |
| F9 | 本地消息存储 | **Must** | Android Room/SQLite 持久化 |
| F10 | 本地消息搜索 | **Must** | FTS 全文检索并定位 |
| F11 | 传输安全 | **Must** | TLS 通道加密 + 登录密码哈希 |
| F12 | 后端并发 | **Must** | Reactor 并发模型（非 thread-per-connection） |
| F13 | 心跳保活 | **Should** | 已平移：30s 心跳 / 90s 超时强踢 |
| F14 | 多端互踢 | **Should** | 已平移：重复登录踢旧端 |
| F15 | **已读回执** | **Should** | 消息状态机：发送中→已送达→已读 |
| F16 | **输入中状态** | **Should** | "对方正在输入…"（临时态，不落库） |
| F17 | 好友列表 | **Should** | 登录下发好友及在线状态 |
| F18 | 本地存储加密 | **Should** | SQLCipher（消息库）+ MMKV 加密（KV） |
| F19 | 群聊 | Could（后续迭代） | roadmap 后续 |
| F20 | 语音/视频、推送、iOS/鸿蒙 | 后续迭代 | 架构预留，不在本期 |

### 3.2 关键用例与验收标准

**UC1 注册/登录**
- 注册新账号（昵称/手机号唯一性校验）→ 登录成功进入好友列表
- 密码错误/用户不存在 → 明确提示
- 验收：新注册账号立即可登录；预置种子用户 A/B/C 可登录

**UC2 文本单聊**
- A→B 在线 → 1s 内送达；B 离线 → 入库，B 上线自动补发
- 验收：双向互发、中文无乱码

**UC3 图片单聊**
- A 选相册图片 → 压缩传输 → B 聊天页显示；服务端 `uploads/` 可见落盘

**UC4 文件传输**
- A 发送文件（如 PDF/zip，10MB 级）→ 双方看到进度 → B 完成接收可打开
- 验收：分块传输、断线重发机制合理（重发不重复写）

**UC5 消息漫游**
- A 卸载重装（或换模拟器）登录 → 拉取到与 B 的历史消息
- **口径（本期定死）**：文本、图片**直接回传内容**；文件**回传记录元信息**（文件名/大小/图标），点击可重新下载
- 验收：分页拉取、与本地合并不重复（msg_id 幂等）；漫游回来的文件记录可见、可重新下载

**UC6 已读回执 / 输入中**
- B 打开会话 → A 侧消息变为"已读"；B 输入时 A 看到"对方正在输入…"
- 验收：状态流转正确，输入中 5s 无操作自动消失

**UC7 本地存储与搜索**
- 杀进程重进聊天记录仍在；关键词 FTS 检索命中并可定位（万条级 < 100ms）

**UC8 传输安全**
- 抓包消息不可读（TLS）；库中密码为加盐哈希

**UC9 并发展示**
- 多客户端同时收发，服务端日志体现多 IO 线程 + 连接 strand 工作

## 4. 非功能需求

| 类别 | 要求 |
|---|---|
| 性能 | 文本端到端（本机回环）< 200ms；图片压缩后 ≤500KB；文件支持 ≥10MB |
| 并发 | 服务端 Reactor 模型，多连接并发，无连接级数据竞争 |
| 安全 | 密码不出链路明文、库存加盐哈希、通道 TLS、本地库可加密 |
| 可落地 | Android 端 Android Studio 可跑；服务端跨平台 CMake 可构建 |
| 可迭代 | 每模块设计取舍有记录（方案 A/B 对比） |
